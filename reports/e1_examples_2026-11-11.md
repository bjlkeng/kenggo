# Masked examples and shared board encoding

**11 November 2026, UTC — `kenggo-6yr.6`.** The example builder verifies frozen
canonical records and split membership, then writes versioned array shards with
separate labels and provenance. The same pre-move encoder serves supervised
examples and future inference. The real corpus still supplies **zero usable
examples**, so its normalizer is explicitly unfitted.

The [reproducibility manifest](../manifests/e1_examples_v1.json) binds the
implementation, schema, inputs, outputs and measured runs. Original SGFs,
canonical move/clock records and derived arrays remain in ignored storage. The
[canonical audit](e1_canonical_2026-11-11.md), source eligibility and game contract
are unchanged. This completes preprocessing implementation, not E1 readiness or
a trained fallback, persona or opponent profile.

## Shared pre-move contract

[`encoding.encode`](../src/kenggo/encoding.py) takes the shared `Game`, an explicit
`Context` and a model history window. It accepts playable states and saved
truncation observations. Truncated observations retain their board for value
bootstrap but have no legal actions; unresolved or terminal states are rejected.
Exact terminal values belong to the rules adapter.

Coordinates stay top-left row-major: SGF `aa` is action 0, `sa` is 18, `as` is 342,
`ss` is 360, and explicit pass is 361. Mover view swaps color planes without
rotating coordinates. There is no resignation action in the learned policy.

| Input array | Shape per example | Meaning |
| --- | --- | --- |
| `board` | `3 × 19 × 19`, boolean | Own stones, opponent stones, simple-ko point |
| `legal` | `362`, boolean | Shared engine's legal-action mask |
| `scalars`, `scalar_valid` | `16`, float32 / boolean | Ordered pre-move values and validity |
| `ranks`, `rank_valid` | `2`, int16 / boolean | Mover/opponent historical ranks; 1–16 map to 15k through 1d; 0 is unknown |
| `history_actions` | `H`, int16 | Oldest to newest prior actions, including pass; left padding is −1 |
| `history_colors` | `H`, int8 | +1 for the current mover's prior actions, −1 for the opponent, 0 padding |
| `history_valid` | `H`, boolean | Distinguishes history from padding |

`H` is 0, 8, 32 or 64. The engine always retains the complete legality history;
the history window never changes board, captures, ko, pass state or legal mask.

The 16 scalars, in order, are mover-is-Black, mover komi, prisoners for the mover,
prisoners for the opponent, pass streak, prior action count, pending cap, truncated
status, cleanup phase, nominal main seconds, nominal period seconds, nominal
period count, mover/opponent clocks and mover/opponent overtime counters. Komi
is −6.5 for Black and +6.5 for White. Prisoners for Black are captured White
stones. Cleanup phase is always zero under the ordinary-play contract.

Known nominal clocks retain their exact tuple within the approved family:
600–1,800 main seconds, 3–5 Japanese periods of 20–60 seconds. `Context` also
supports unknown ranks and `nominal_clock=None` for the missing/untimed context.
The last four dynamic scalars are always zero with false validity, and all
duration targets are masked under [timing v1](../plan/e1_game_and_data_contract.md#timing-version-1).
Zero is a storage placeholder, not a measured duration or clock.

The context accepts only ranks and nominal settings. Source results, final replay
status, adjudication, target actions, future moves, raw clocks, source identifiers
and persona keys are absent from these input arrays. `apply_normalizer` accepts
exactly `INPUT_KEYS`; passing labels with the inputs is rejected.

## Admission, examples and persona metadata

[`examples`](../src/kenggo/examples.py) requires independent canonical-file and
split-manifest pins, verifies every canonical payload digest, and checks exact
source-ID/role membership, groups, identity flags and action counts. Production
loading accepts only the reviewed canonical/split hashes. Positive synthetic
inputs require explicit fixture-only manifests; that scope persists into their
shards and normalizer. A later admitted corpus needs a reviewed source revision.

Before releasing the first example of a usable game, the builder replays its
whole history and verifies the canonical final snapshot, lifecycle and pending
cap. An illegal suffix cannot salvage an earlier training prefix. Example `ply`
uses the state after actions `[:ply]` and labels exactly action `[ply]`. EOF adds
nothing. Every row records the canonical and SGF hashes, source ID, SGF node,
pre-move snapshot and index. These references preserve the complete history
without copying it into every model row.

Excluded and embargo games produce no examples. Adaptation prefixes emit only
their authorized target colors, replaying intervening opponent moves normally;
prefix value validity is always false. Other usable roles retain observed policy
actions. Value labels require both canonical outcome support and split permission;
the Black result is negated for White-to-move. Missing/timeout/forfeit results
remain value-masked. Labels have separate `policy_valid`, `value_valid` and
`duration_valid` flags.

Persona information lives only in the Parquet provenance: group keys, verified
identity status, known-persona availability and adaptation permission. It is not
part of shared policy/value features. A later held-out target is identified by
the pinned reserved cohort, not by the prefix-only `adaptation_colors` field.
Its default row does not imply an adapted embedding exists; the future trainer
must separately supply frozen, validation-selected adaptation. Known-persona
annotations describe available training evidence, not a trained checkpoint.

## Rank masking and normalization

The default training configuration uses seed **20261111**, with independent
probabilities **100/1000 for masking the mover rank** and **200/1000 for masking
the opponent rank**. These are project choices, not evaluated rates. A digest of
seed/source ID/ply/player role makes the choices independent of shard order.
Each row logs both hidden flags while preserving the original historical ranks.
Development, confirmation, adaptation and final roles receive no such augmentation.
This prepares both unknown-rank paths for future training; none is trained yet.

`fit_normalizer` reads only the pinned `train` shards. Stable online accumulation
fits population means and standard deviations for valid prisoner counts, prior
action count and nominal clock settings, using policy-valid training rows. Rank IDs, masks, labels and
dynamic clocks are never fitted. Constant scales become one; features with no
training observations retain zero counts and are masked when applying a fitted
normalizer. An entirely empty training partition yields `fitted=false`, which
`apply_normalizer` rejects. Fixture statistics remain marked fixture-only.

## Storage and reproduction

Each role has deterministic NPZ array shards and matching typed Parquet
provenance, with a default limit of 256 examples per shard. Empty roles still
receive an explicit zero-row schema. `read_shards(directory, expected_sha256,
role)` requires a caller-pinned manifest, validates file hashes, names, dtypes and
shapes, and loads arrays without pickle. Consumers select `INPUT_KEYS` for model
inputs and keep labels and persona metadata separate.

From the [locked CPU workspace](../docs/workspace.md), with retained canonical
artifacts and a fresh destination:

```bash
export UV_CACHE_DIR="$PWD/.cache/uv"
export UV_PYTHON_INSTALL_DIR="$PWD/.cache/python"
uv run --locked python -m kenggo.examples_audit \
  runs/e1-canonical-2026-11-11-v4 runs/e1-examples-new
uv run --locked python -m unittest discover -s tests -p test_encoding.py -v
uv run --locked python -m unittest discover -s tests -p 'test_example*.py' -v
```

`--history` accepts 0/8/32/64. Existing output directories are never replaced.
The audit uses one worker, at most 1,000 canonical records, 64 MiB compressed
canonical input, 256 MiB canonical JSON, 120 CPU seconds and 180 wall seconds.
It makes no HTTP requests and uses no GPU. Data hashes bind content; they do not
prove that a future evaluator kept the final holdout unopened. The original
split execution requirements remain in the example manifest.

## Validation result and limits

The bounded diagnostic selects the first source URL in each of five supported
result categories, then checks first/middle/last/first-pass indices without
duplicates. These are engineering fixtures sampled from already inspected,
source-ineligible records; their gates are never changed and they emit no
training examples.

| Source result | Recorded actions in selected game | Checked positions |
| --- | ---: | ---: |
| Scored | 306 | 4 |
| Resignation | 284 | 3 |
| Timeout | 203 | 3 |
| Forfeit | 173 | 3 |
| Missing/unknown | 10 | 3 |

All **16 positions** agree across four history windows with the shared board and
legal mask and a separately reconstructed full-history state: **zero mismatches**.
The five games contain 976 distinct recorded actions; verification replays their
histories and prefixes more than once. This is not a new native corpus comparison
or a statistical coverage claim. All 1,000 source records remain excluded from
usable roles; every example count and normalization-fit count is zero.

Synthetic tests cover positive shard creation, coordinates, captures, komi/value
signs, ko/recurrence and history, whole-game rejection, per-color prefixes,
missingness, rank masking, train-only fitting, hashes and deterministic output.
The first corpus attempt exposed an overly narrow nominal-clock check: it
accepted only the fixture tuple. Regressions failed before the fix, then passed
for both family boundaries and fractional settings. The partial attempt retained
empty shards and an unfitted normalizer; its CPU/total wall time was not recorded.
It is listed as failed, not as a successful run.

Independent review then found variance cancellation in the original normalizer:
a constant 900.1-second setting acquired a tiny positive scale, distorting nearby
inference inputs. A 167-action regression failed before the fix and now verifies
unit scale for that constant feature, correct variation for move counts and the
expected normalization of a 900.2-second input. Stable online accumulation replaces the
subtraction of nearly equal squared sums.

Two final runs reproduce the example manifest, all role shards, normalizer and
diagnostics exactly. The manifest also retains the two complete runs superseded
by the normalization repair and the earlier failed clock-family attempt.
The cost records cover input verification, writing and sampled replay; they
exclude imports, final summary writing, tests,
authoring and independent review. These are bounded cost records, not throughput
or performance comparisons. Affirmative source evidence (`6yr.11`) and usable
certified endings (`6yr.10`) still block the readiness check in `6yr.7`.
