# E2 tracking and checkpoint evidence

Bead `kenggo-ydo.1` adds local run records, W&B tracking, reproducible
checkpoints and a GPU allocation ledger. The [accepted synthetic CPU
run](https://forge.coreweave.com/wandb/bjlkeng/kenggo/runs/2e02b3a00c1e4003903a24897568d0ab)
passed an actual online resume and checkpoint download check. This establishes
tracking for subsequent E2 work; it supplies no Go baseline, throughput,
playing-strength or GPU-readiness result.

The destination is the private W&B project `bjlkeng/kenggo`, selected from the
existing authenticated account. Credentials are not part of the saved evidence.
The [evidence manifest](../manifests/e2_tracking_v1.json) pins the executed
configuration, source modules, environment locks, local run records, checkpoint,
downloaded artifact and validation logs. The run's provenance and binary source
patch identify the exact code before its final source commit. The [usage
guide](../docs/experiments.md) gives the reproduction command and API contracts.

## What was verified

The [frozen smoke configuration](../configs/e2_tracking_smoke_v1.json) uses a
small synthetic model with dropout, an optimizer and a scheduler. It records a
partial attempt after one update, then reopens the same W&B run and restores
model, optimizer, scheduler, training progress and RNG state. The next stochastic
update exactly matches uninterrupted execution. A second checkpoint is uploaded,
downloaded through the service API and checked against its independently saved
manifest hash and model state. The remote summary confirms both attempt outcomes,
their costs and zero GPU use.

The source configuration pins current E1 v3 data, split, example, normalizer,
rules/referee and environment manifests. This check hashes those inputs without
decoding Go examples or uploading source games. The two owner exclusions remain
in force; reserved final targets remain sealed.

An earlier [run](https://forge.coreweave.com/wandb/bjlkeng/kenggo/runs/430587a44bba48dd91b05bbc990f2d27)
passed checkpoint continuation but exposed stale nested cost fields on remote
readback after resume. It is retained as superseded evidence, including its
costs. The fix writes distinct flat fields for every attempt, and the accepted
run explicitly verifies them. Interrupted processes with unknown costs remain
marked incomplete rather than appearing fully accounted for.

Independent review found two additional continuation defects. Checkpoints now
preserve every module's train/eval mode, and a run stays recoverable while W&B
shutdown is pending. Regressions reproduced both failures before the fixes. The
final online run uses checkpoint format v2; earlier runs retain their original
format and archived source. A killed shutdown no longer leaves an unrecoverable
completed status, and unknown shutdown costs remain explicit.

The GPU ledger preserves reservations across process failure, charges failed
and partial allocations, supports shared-arm attribution and blocks new
reservations after an overrun. Callers still own measuring allocation intervals
and stopping jobs. No GPU allocation was made for this tracking check.

## Validation and costs

Both the pinned CPU environment and the CUDA package environment passed all
211 tests with the pinned native rules reference enabled, with zero skips.
Tests cover exact continuation, component and hash mismatches, immutable
artifacts, failed/offline/interrupted runs, writer exclusion, remote summary
integrity, pre-upload byte limits and concurrent resource accounting. The CUDA
environment suite ran on CPU; it does not establish CUDA execution support.

`uv lock --check`, `uv sync --locked --check`, the CPU smoke command,
`uv build --no-sources`, the CUDA package consistency check and Git whitespace
checks pass. All 32 original CUDA package versions are preserved; the 32 added
tracking dependencies match the CPU lock. The independent review verdict and
delivery commit are recorded in Beads.

Across the three smoke runs and six attempts, measured calling-process CPU time
was 4.7700 seconds, elapsed body time was 45.5397 seconds, attempted checkpoint
uploads totaled 1,433,132 bytes, and GPU use was zero. These remain within the
cumulative allowance of 120 CPU seconds, 180 elapsed seconds and 10 MiB.
These are setup checks, not comparative performance measurements. Imports,
dependency preparation and complete background-service CPU totals are outside
those smoke-body measurements; local attempt records separately retain tracking
shutdown time.

Dependency preparation exceeded its separate 256 MiB new-package allowance:
an attempted direct-wheel resolution unexpectedly downloaded a 514.2 MiB Torch
wheel, as reported by `uv`. The download finished before it could be stopped.
Further downloads were stopped. That source prototype was discarded; the final
hash-pinned CUDA registry lock and installation were completed entirely offline
from cached packages. Full setup CPU and network totals were not instrumented.
This breach is retained in the evidence and is not charged as GPU training.

## Remaining scope

The compact learner, match runner, Human SL reference and bounded BASE pilot
remain separate E2 tasks. After the owner restarted the host, NVIDIA discovery
reports matching 595.99.02 driver versions. Actual CUDA execution is verified
separately by `kenggo-ydo.7`. No training budget or E2 readiness decision is
implied by this tracking result.
