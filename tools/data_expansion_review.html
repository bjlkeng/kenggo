The network and larger dataset

E2 builds a model that predicts human Go moves. The first model used a small pilot dataset. This page explains that model and checks the new data prepared under your 24-hour limit.

In the small pilot, the model trained with ranks had worse average move-prediction loss than the version trained without ranks. No model has yet been trained on the larger dataset, so it does not establish an improvement.

What to review

  1. Read the model explanation. For E2, both the move and game-result outputs learn from recorded labels. This explains why a supervised model has two losses.
  2. Check the new move count and rank coverage. For kenggo-ydo.8, compare the usable training rows with the 100,000-move minimum. Check weak-rank gaps too: more moves from a few players do not cover every difficulty setting.
  3. Step through a few sample positions. For kenggo-ydo.8, check that stones, the next human move and the recorded outcome make sense. The replay uses the project's checked rules engine.
  4. Save any concerns in the notes below. These notes can guide E2's next training run and its open readiness check, kenggo-ydo.6. No new model result is implied by the larger dataset.

Policy and value are both supervised

Policy: which move did the human play?

The label is the recorded next move. The loss is cross-entropy: it gets smaller when the model gives that move more probability.

There are 362 choices: 361 intersections and pass. Illegal actions are masked out.

Value: did the mover eventually win?

The label is +1 for a win, −1 for a loss, from the current mover's view. The loss is the average squared prediction error.

Unknown, timeout and forfeit outcomes are excluded from this loss. The policy label can still be usable.

total loss = mean policy cross-entropy + mean valid value squared error

This stage uses recorded human games. It does not use reinforcement learning or search-generated training moves.

Inputs, layers, outputs and training settings

Size: 2,410,515 trainable parameters. The comparison without ranks has the same architecture and parameter count; its rank inputs are hidden.

4 board planes
+ state and rank inputs→128-channel stem
+ 8 residual blocks→362 move scores
+ 1 outcome value

Inputs: four 19 × 19 planes show mover stones, opponent stones, ko and legal placements. Sixteen state/time fields have sixteen validity flags. Each player's rank has a 16-number learned embedding and a validity flag. These make a 66-number metadata vector.

The sixteen fields are mover color, mover-relative komi, prisoners for each side, consecutive passes, move number, pending stop, truncation and cleanup flags, main-time seconds, overtime-period seconds, number of periods, and remaining time and overtime status for each side. Dynamic clock values are unavailable and stay masked. The model has no previous-move planes; the rules engine still keeps the full game history.

Layers: the board stem is a 3 × 3 convolution with 128 channels. A 66 → 128 → 128 metadata network is added across the board. Each of eight residual blocks has two 3 × 3 convolutions with 128 channels, group normalization and ReLU, plus a skip connection.

Outputs: a 1 × 1 convolution produces board-move scores; an average-pooled board vector produces the pass score. The value head uses average pooling, a 128 → 128 → 1 network and tanh, giving a number between −1 and +1.

Pilot settings: Adam, learning rate 0.001, batch size 128, 20 epochs. Each arm saw the same 22,916 training moves repeatedly. Development evaluation used 5,926 moves from 24 games. The 15,223 moves in 70 final games remain sealed.
