# Technical writing

Lead with the reader's task or the concrete result. Decide whether the document is a procedure, reference, tutorial, or explanation, and organize it around that need. Link supporting detail instead of repeating it.

Use the actual symbol, file, command, and metric names. Explain unfamiliar terms once. Put conditions before the actions they govern. Keep one instruction per step and make the expected result observable. Check commands against the installed interface before publishing them.

Separate observed results, inference, and proposed work. Pair measurements with their method and provenance. Do not present project choices as established scientific results.

Keep README additions proportionate to the requested scope. Commit messages describe the problem and resulting behavior, with the bead ID and relevant validation or review-driven fixes. Apply [pstack-unslop](../pstack-unslop/SKILL.md) before finishing.
